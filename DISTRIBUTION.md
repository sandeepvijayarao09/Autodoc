# Shipping Autodoc the way Apple does

The release pipeline (`./release.sh`) already produces everything Apple's build
system produces **except the two things that legally require a paid Apple
Developer account**: a *Developer ID Application* certificate and a
*notarization ticket*. This file is the last mile.

## What `./release.sh` gives you today

| Step | Apple-standard? | Here |
|---|---|---|
| Compiled native arm64 binary | ✅ | `swift build -c release` |
| App icon (`.icns`, full iconset) | ✅ | generated by `makeicon.swift` |
| Versioned Info.plist (category, copyright, hi-res) | ✅ | `Info.plist` |
| Hardened Runtime + entitlements | ✅ | `flags=…,runtime`, `Autodoc.entitlements` |
| Code signature | ⚠️ ad-hoc | needs Developer ID cert (below) |
| `.dmg` with drag-to-Applications | ✅ | `Autodoc-<VERSION>.dmg` |
| Notarization + stapled ticket | ❌ | needs Apple account (`./notarize.sh`) |

An **ad-hoc** hardened build runs on *this* Mac. To run on *any* Mac without
Gatekeeper warnings, you need the two steps below.

## 1. Enroll (one time, ~$99/yr)

1. Join the **Apple Developer Program**: <https://developer.apple.com/programs/>
2. In **Xcode → Settings → Accounts**, add your Apple ID and click
   **Manage Certificates → + → Developer ID Application**. This installs the
   signing certificate into your login keychain.

Verify it landed:
```sh
security find-identity -v -p codesigning | grep "Developer ID Application"
```

## 2. Store a notary credential (one time)

Create an app-specific password at <https://account.apple.com> → Sign-In &
Security → App-Specific Passwords, then:
```sh
xcrun notarytool store-credentials autodoc-notary \
    --apple-id "you@example.com" \
    --team-id  "ABCDE12345" \
    --password "xxxx-xxxx-xxxx-xxxx"
```

## 3. Build + notarize (every release)

```sh
./release.sh      # now auto-detects your Developer ID and signs with it + timestamp
./notarize.sh     # notarizes + staples the app, rebuilds the DMG, notarizes it too
```

`release.sh` already prefers a real *Developer ID Application* identity the
moment one exists in your keychain — no edits needed. It reads the version from
`./VERSION` and stamps it into `Info.plist`, so bumping a release is a one-line
change. After `notarize.sh`,
`spctl --assess` will report **accepted**, and the `.dmg` is distributable to
anyone.

## Mac App Store instead?

Different track: add the **App Sandbox** entitlement, sign with an *Apple
Distribution* cert, and submit a `.pkg` via **Transporter** / App Store Connect.
Screen-recording apps are allowed but must justify the usage in review, and
sandboxing ScreenCaptureKit needs the user to pick the display via the system
picker. Left out here on purpose — Developer ID + notarization is the right
distribution channel for a personal menu-bar utility.
